# รายงาน M0: ตรวจการเข้าถึงข้อมูล

ทดสอบเมื่อ 2026-10-09 บน cloud container (Linux) ไม่ใช่เครื่อง laptop ของผู้ใช้
รันซ้ำได้ด้วย `python scripts/m0_check.py --plastics-repo <path ของ repo earthrise-media/plastics>`

## สรุป

| แหล่งข้อมูล | ผล | หมายเหตุ |
|---|---|---|
| Earth Search STAC `sentinel-2-c1-l2a` | ✅ ใช้ได้ | ค้นและอ่านภาพแบบ windowed read ได้จริง ไม่ต้องใช้บัญชี |
| Planetary Computer STAC (สำรอง) | ✅ ใช้ได้ | ขอ token แบบไม่ระบุตัวตนแล้วเปิดภาพได้ |
| Global Plastic Watch API | ❌ ใช้ไม่ได้ | ทุก endpoint ต้องใช้ API key (ได้ HTTP 401) ตาม brief จึงไม่สมัครเอง |
| โฟลเดอร์ `data/` ใน repo earthrise (สำรองของ GPW) | ✅ ใช้ได้ | มีบ่อขยะในไทย 154 แห่ง |
| OpenStreetMap Overpass | ⚠️ ทดสอบจาก cloud ไม่ได้ | ถูก network policy ของ container นี้ปิดไว้ ต้องทดสอบใหม่บน laptop |
| ไฟล์ OSM ของไทยจาก Geofabrik | ⚠️ ทดสอบจาก cloud ไม่ได้ | สาเหตุเดียวกับข้างบน |
| สเปกเครื่องผู้ใช้ | ⏳ ยังไม่ได้ตรวจ | ต้องตรวจบน laptop |

## 1. ภาพ Sentinel-2

- collection ที่ใช้: `sentinel-2-c1-l2a` (Collection 1) อีกสอง collection คือ `sentinel-2-l2a` และ `sentinel-2-pre-c1-l2a` ยังมีอยู่ แต่ Collection 1 เป็นชุดที่ประมวลผลใหม่ให้มาตรฐานเดียวกันทั้งหมด
- มีครบ 12 แบนด์ตามงานวิจัย: `coastal`(B1) `blue`(B2) `green`(B3) `red`(B4) `rededge1-3`(B5-7) `nir`(B8) `nir08`(B8A) `nir09`(B9) `swir16`(B11) `swir22`(B12) และมี `scl` สำหรับกรองเมฆ
- การแปลงค่า: reflectance = DN × 0.0001 − 0.1 (ต้องใช้ offset −0.1 ด้วย ไม่อย่างนั้นค่าจะเพี้ยน)
- ความละเอียดแต่ละแบนด์ไม่เท่ากัน (10/20/60 ม.) ต้อง resample ให้เท่ากันก่อนใช้

**จุดทดสอบ:** บ่อขยะจากไฟล์ยืนยันของ earthrise ที่ lat 7.95933, lon 99.02872 (ภาคใต้)

| รายการ | ผล |
|---|---|
| จำนวนภาพ ก.ค.–ก.ย. 2026 (หน้าฝน) รัศมี 5 กม. | 46 ภาพ จาก 2 tile (47NMJ, 47NNJ) |
| เวลาอ่าน 13 asset ของ 1 ภาพ | 5 กม.: 14 วิ (ครั้งแรก รวมเวลาเปิดไฟล์), 10 กม.: 1.6 วิ, 20 กม.: 5 วิ |
| พิกเซลที่มีภาพไม่ติดเมฆอย่างน้อย 1 ครั้ง (หน้าฝน) | 99.9% |
| พิกเซลที่มีภาพไม่ติดเมฆอย่างน้อย 3 ครั้ง (หน้าฝน) | 98.9% (ค่ากลาง 12 ครั้ง) |
| พิกเซลที่มีภาพไม่ติดเมฆอย่างน้อย 3 ครั้ง (ม.ค.–มี.ค.) | 99.9% (ค่ากลาง 17 ครั้ง) |

ข้อสังเกต:
- ตัวเลขเวลาที่รัศมี 10 และ 20 กม. ต่ำเกินจริง เพราะเปิดไฟล์ไว้แล้วจากรอบแรก หนึ่งรอบจริงต้องอ่านภาพหลายสิบภาพ ทั้งช่วง "ก่อน" และ "หลัง" **ประเมินคร่าว ๆ ว่ารัศมี 5 กม. ใช้หลายนาที** ตัวเลขจริงจะวัดใน M1 และขึ้นกับความเร็วเน็ตของ laptop
- ผลเรื่องเมฆดีกว่าที่คาด แต่วัดจากจุดเดียว 3 เดือน ภาคอื่นหรือเดือนอื่นอาจแย่กว่านี้ แอปยังต้องมีระบบเตือนเรื่องเมฆตาม brief

## 2. ตัวอย่างบ่อขยะจากข้อมูลเปิด

Global Plastic Watch ต้องใช้ API key จึงใช้ข้อมูลใน repo `earthrise-media/plastics` แทน:

| ประเทศ | จำนวนจุดยืนยัน (positive) |
|---|---|
| ไทย | 154 |
| เวียดนาม | 198 |
| มาเลเซีย | 101 |
| เมียนมา | 50 |
| กัมพูชา | 48 |
| ลาว | 17 |

- **เกินเกณฑ์ 30 แห่งของ brief มาก ชั้น B จึงทำได้**
- มีตัวอย่างลบ (ไม่ใช่ขยะ) ด้วย เช่น `vietnam_v0.4_patch_negatives` (52), `malaysia_v0.4_patch_negatives` (85) และชุดดินเปล่าของบาหลี
- ข้อควรระวัง:
  - จุดเหล่านี้คือจุดที่โมเดลของ earthrise ตรวจพบ แล้วคนยืนยันจากภาพช่วง 2019–2021 บางแห่งปัจจุบันอาจปิดหรือถูกกลบไปแล้ว ต้องตรวจกับภาพปี 2026 ก่อนใช้ฝึก
  - เป็นจุด ไม่ใช่ polygon ต้องสร้าง patch รอบจุดแล้วกรองพิกเซลเอง (เช่น NDVI > 0.4 ออก)
  - เป็นจุดที่โมเดลเดิมหาเจอ จึงลำเอียงไปทางบ่อขยะชุมชนขนาดใหญ่
  - **license เป็น CC BY-NC 4.0** ใช้ได้เฉพาะงานไม่แสวงกำไร และต้องอ้างอิงที่มา

## 3. โมเดลเดิมใน `models/`

ตรวจด้วย h5py (ยังไม่ได้ติดตั้ง TensorFlow):
- ไฟล์ `.h5` บันทึกด้วย Keras 2.4–2.6 ไฟล์โหลดได้ครบ ไม่ใช่ LFS stub
- โมเดลล่าสุดตามสถาปัตยกรรมในงานวิจัยคือ `spectrogram_v0.0.11.1_2021-11-14.h5`
  - input (12, 2, 1)
  - **Conv2D ชั้นที่สองใช้ kernel (3,1) ไม่ใช่ (3,2) อย่างที่ brief เขียน** เพราะหลังชั้นแรก ความกว้างเหลือ 1 จึงใช้ (3,2) ไม่ได้ ตอนฝึกเองใน M3 จะใช้ (3,1)
  - config ระบุว่าฝึกจากภาพรวม 3 เดือนด้วยค่าต่ำสุด (`method_min`) จาก L1C ในอินโดนีเซีย
- ตามที่ brief กำหนด จะใช้โมเดลเดิมเป็นการทดลองเท่านั้น เพราะฝึกจาก L1C ส่วน demo ใช้ L2A
- framework ที่เลือก: **PyTorch แบบ CPU** สำหรับฝึกเอง ใช้กับ Windows ได้ตรงและโมเดลเล็กมาก ส่วนการทดลองโหลด `.h5` เดิมต้องใช้ TensorFlow/Keras ซึ่งจะทำแยกเป็นทางเลือก

## 4. แผนที่ปรับตามผลจริง

1. **GPW** → ใช้ไฟล์จาก repo earthrise แทน (154 แห่งในไทย + ประเทศใกล้เคียง)
2. **ชุดทดสอบ "บ่อที่รู้ตำแหน่ง" (ข้อ 6.1 ของ brief)** → brief ให้ใช้ OSM แต่ทดสอบ OSM จาก cloud ไม่ได้
   - ถ้า Overpass ใช้ได้บน laptop: ใช้ `landuse=landfill` จาก OSM ตามเดิม
   - ถ้าใช้ไม่ได้: กันจุดของ earthrise ในไทยส่วนหนึ่งไว้เป็นชุดทดสอบ โดยแยกตามสถานที่ (ต้องให้ผู้ใช้อนุมัติก่อน)
3. **ถนนและแหล่งน้ำ (M4)** → ต้องใช้ OSM ต้องทดสอบบน laptop
4. **ตรวจสเปกเครื่อง** → ทำบน laptop ตอนเริ่ม M1

## 5. สิ่งที่ยังต้องทำบน laptop ก่อน M1

```cmd
cd dump-finder
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
git clone --depth 1 https://github.com/earthrise-media/plastics ..\plastics
.venv\Scripts\python scripts\m0_check.py --plastics-repo ..\plastics
```
ถ้าบรรทัด `Overpass:` ขึ้นเป็น `HTTP 200` แปลว่า OSM ใช้ได้บนเครื่องนั้น
