# Demo brief: เครื่องมือค้นหาจุดต้องสงสัยบ่อขยะจากพิกัดและรัศมี

เอกสารนี้ใช้ส่งงานให้ Claude Code สร้าง **demo ที่รันได้จริงบนเครื่องผู้ใช้**
ผู้ใช้ไม่มีข้อมูลหน่วยงานและไม่มีบัญชีบริการดาวเทียมให้ในขั้นนี้ ทุกอย่างต้องเริ่มจากข้อมูลเปิด
แผนฉบับเต็ม (ข้อมูลหน่วยงาน เทคนิคเสริม การติดตามรายเดือน) อยู่ใน `illegal-dump-detection-brief.md`
ใช้เป็นแนวทางขยายภายหลัง ไม่ต้องทำใน demo นี้

## 1. สิ่งที่ผู้ใช้ต้องการ

ผู้ใช้เลือกจุดบนแผนที่หรือกรอกพิกัด กำหนดรัศมีเป็นกิโลเมตร แล้วกดรัน ระบบต้อง:

1. ดึงภาพดาวเทียมของพื้นที่ในรัศมีนั้น
2. ประมวลผลหาว่ามีบ่อขยะ กองขยะ หรือการนำขยะมาทิ้งใหม่หรือไม่
3. แสดงจุดต้องสงสัยบนแผนที่พร้อมหลักฐาน เพื่อให้เจ้าหน้าที่ลงพื้นที่ตรวจสอบ

ระบบทำหน้าที่ชี้เป้าเท่านั้น ผลลัพธ์คือ "จุดต้องสงสัย" ไม่ใช่ข้อสรุปว่ามีการลักลอบทิ้ง

## 2. หน้าจอและการใช้งาน

เว็บแอปที่รันบนเครื่องผู้ใช้ (Windows) เปิดด้วยคำสั่งเดียวหรือไฟล์ `run.bat`

**ส่วนรับค่า**
- แผนที่ให้คลิกเลือกจุด และช่องกรอกละติจูด/ลองจิจูด
- รัศมี: ค่าเริ่มต้น 5 กม. สูงสุด 20 กม. (จำกัดไว้เพื่อให้ demo รันจบในเวลาที่รอได้)
- ช่วงเวลาที่ต้องการตรวจ: ค่าเริ่มต้นคือ 3 เดือนล่าสุด
- ระดับความไว: สูง (ค่าเริ่มต้น) / กลาง / ต่ำ
- ปุ่มรัน พร้อมแถบความคืบหน้าและเวลาโดยประมาณ

**ส่วนแสดงผล**
- ประโยคสรุป เช่น "พบจุดต้องสงสัย N จุด ในรัศมี X กม."
- แผนที่แสดงวงรัศมีและหมุดจุดต้องสงสัย แยกสีตามประเภท
- ตารางเรียงตามคะแนน
- การ์ดของแต่ละจุด: ภาพก่อนและหลัง (สีจริงและ false color ที่ใช้ SWIR) ขนาดพื้นที่ วันที่เริ่มพบ
  ระยะถึงถนนและแหล่งน้ำ และลิงก์เปิดพิกัดในแผนที่ภายนอกสำหรับนำทาง
- ปุ่ม export: CSV, GeoJSON และ KML (สำหรับเปิดในมือถือตอนลงพื้นที่)
- ข้อความเตือนถาวรบนหน้าจอ: ผลเป็นจุดต้องสงสัย ต้องตรวจยืนยันก่อนใช้

**ประเภทของจุดต้องสงสัย**
- `existing`: ลักษณะคล้ายกองขยะ และมีอยู่ก่อนช่วงเวลาที่ตรวจ
- `new`: ลักษณะคล้ายกองขยะ และเพิ่งปรากฏหรือขยายตัวในช่วงเวลาที่ตรวจ
- `disturbed`: พื้นที่ถูกเปิดหน้าดินหรือเปลี่ยนแปลง แต่ยังบอกไม่ได้ว่าเป็นขยะ

## 3. แหล่งข้อมูล (ไม่ต้องใช้บัญชี)

ตรวจสถานะและวิธีเข้าถึงจากเอกสารปัจจุบันใน M0 ก่อนใช้ อย่าใช้จากความจำ

| ข้อมูล | แหล่งหลัก | แหล่งสำรอง |
|---|---|---|
| ภาพ Sentinel-2 L2A (COG) | Earth Search STAC: `https://earth-search.aws.element84.com/v1` collection `sentinel-2-l2a` หรือ `sentinel-2-c1-l2a` | Microsoft Planetary Computer STAC (ขอ token แบบไม่ระบุตัวตนผ่านแพ็กเกจ `planetary-computer`) |
| ถนน แหล่งน้ำ บ่อขยะที่ปักไว้ | OpenStreetMap (Overpass API) | ไฟล์ extract ของประเทศไทย |
| บ่อขยะที่งานวิจัยยืนยันแล้ว | Global Plastic Watch: `https://api.globalplasticwatch.org/` | โฟลเดอร์ `data/` ใน repo `earthrise-media/plastics` |
| โมเดลที่ฝึกแล้ว (ใช้ทดลองเท่านั้น) | โฟลเดอร์ `models/` ใน repo `earthrise-media/plastics` | - |

หมายเหตุสำคัญ:
- ใช้ 12 แบนด์: B1–B9, B8A, B11, B12 (L2A ไม่มี B10 ซึ่งงานวิจัยก็ไม่ได้ใช้)
- อ่านภาพแบบ windowed read เฉพาะพื้นที่ในรัศมี ห้ามดาวน์โหลดทั้ง tile
- โมเดลใน repo ฝึกจากภาพ L1C (Top-of-Atmosphere) แต่ demo นี้ใช้ L2A (surface reflectance)
  ค่าพิกเซลไม่ตรงกัน **ห้ามใช้โมเดลเดิมเป็นตัวตัดสินหลัก** ลองได้แต่ต้องรายงานแยกว่าเป็นการทดลอง
- Sentinel-1 และ Landsat บน Earth Search เป็น requester-pays ไม่ใช้ใน demo นี้
- ถ้าแหล่งใดเข้าไม่ได้หรือต้องเสียเงิน ให้หยุดและรายงานผู้ใช้ ห้ามสมัครบริการหรือใส่ข้อมูลชำระเงินเอง

## 4. วิธีตรวจจับ

ทำเป็น 2 ชั้น ชั้น A ต้องใช้งานได้ก่อน แล้วค่อยเพิ่มชั้น B

### 4.1 การเตรียมภาพ
- กรองเมฆและเงาเมฆด้วยแบนด์ SCL
- ภาพ "หลัง": รวมภาพในช่วงเวลาที่ตรวจ (ค่าเริ่มต้น 3 เดือนล่าสุด)
- ภาพ "ก่อน": รวมภาพช่วงเดือนเดียวกันของปีก่อนหน้า เพื่อไม่ให้ฤดูกาลทำให้เข้าใจผิด
- วิธีรวมภาพ: ทดลองเทียบ median กับ percentile ต่ำ แล้วเลือกแบบที่เหลือเมฆน้อยกว่า
  (งานวิจัยใช้ค่าต่ำสุดกับภาพ L1C แต่ยังไม่มีหลักฐานว่าเหมาะกับ L2A)
- ถ้าพิกเซลที่ใช้ได้ในช่วงเวลานั้นน้อยเกินไป (เมฆมาก) ให้แจ้งผู้ใช้และเสนอขยายช่วงเวลา
  ห้ามรายงานว่า "ไม่พบ" ในพื้นที่ที่มองไม่เห็น

### 4.2 ชั้น A: คัดกรองพื้นที่เปลี่ยนแปลง (ไม่ต้องฝึกโมเดล)
- คำนวณดัชนีจากภาพก่อนและหลัง: NDVI, ดัชนีดินเปล่า, ความสว่าง และดัชนีที่ใช้ SWIR
- หาพื้นที่ที่ไม่ใช่น้ำ ไม่มีพืชคลุม และเปลี่ยนแปลงชัดเจนระหว่างก่อนกับหลัง
- รวมพิกเซลที่ติดกันเป็นกลุ่ม ตัดกลุ่มที่เล็กกว่า 0.1 เฮกตาร์ (ประมาณ 3×3 พิกเซล)
- ผลของชั้นนี้ให้ประเภท `disturbed` เท่านั้น เพราะแยกขยะออกจากงานก่อสร้าง บ่อดิน หรือไร่ที่ไถแล้วไม่ได้

### 4.3 ชั้น B: ตัวจำแนกขยะ (ฝึกจากข้อมูลเปิด)
- **ตัวอย่างขยะ:** บ่อขยะในไทยและประเทศใกล้เคียงจาก Global Plastic Watch และ polygon
  `landuse=landfill` ใน OpenStreetMap ตัดพิกเซลที่ NDVI > 0.4 ออก
- **ตัวอย่างไม่ใช่ขยะ:** เน้นพื้นที่ที่สเปกตรัมคล้ายขยะ ได้แก่ ดินเปล่า เขตเมือง เหมืองและบ่อดิน
  ไซต์ก่อสร้าง โรงเรือนพลาสติก โดยอ้างอิงตำแหน่งจาก OpenStreetMap
- **โมเดล:** pixel classifier ตามงานวิจัย input (12, 2) คือ 12 แบนด์ × 2 ช่วงเวลาห่างกัน 6 เดือน
  Conv2D 16 filters (3,2) ReLU → Conv2D 32 filters (3,2) ReLU → Flatten → Dense 32 ReLU
  → Dense 32 ReLU → Dropout 0.1 → Dense 32 ReLU → Dense 2 Softmax
  Adam, learning rate 0.001, batch size 128
- **การแบ่งข้อมูล:** แยกชุดทดสอบตามสถานที่ ห้ามให้บ่อเดียวกันอยู่ทั้งชุดฝึกและชุดทดสอบ
- **การหาจุด:** threshold แผนที่คะแนน แล้วใช้ `skimage.feature.blob_doh`

| ระดับความไว | Pixel threshold | min_sigma |
|---|---|---|
| ต่ำ | 0.9 | 5.0 |
| กลาง | 0.6 | 5.0 |
| สูง (ค่าเริ่มต้น) | 0.6 | 3.5 |

- **การจัดประเภท:** จุดที่ชั้น B ให้คะแนนสูงทั้งในภาพก่อนและหลังเป็น `existing`
  จุดที่คะแนนสูงเฉพาะในภาพหลัง หรือพื้นที่ขยายชัดเจน เป็น `new`
- ถ้าดึงตัวอย่างจากข้อมูลเปิดไม่ได้ หรือได้น้อยกว่า 30 แห่ง ให้รายงานผู้ใช้
  แล้วใช้ชั้น A ต่อไป ห้ามสร้างตัวอย่างขึ้นเอง

### 4.4 วันที่เริ่มพบ
สำหรับจุดต้องสงสัยเท่านั้น (ไม่ทำทั้งพื้นที่) สร้างอนุกรมเวลารายไตรมาสย้อนหลัง 2–3 ปี
แล้วรายงานไตรมาสแรกที่สัญญาณเริ่มปรากฏ

## 5. ลำดับงาน

แต่ละขั้นต้องรันได้จริงและให้ผู้ใช้ดูผลก่อนไปขั้นถัดไป

**M0: ตรวจการเข้าถึงข้อมูล**
- ค้น STAC และอ่านภาพจริงของพื้นที่เล็ก ๆ ในไทย 1 จุด
- ตรวจว่าดึงพิกัดบ่อขยะจาก Global Plastic Watch และ OpenStreetMap ได้หรือไม่ ได้กี่แห่งในไทย
- ตรวจสเปกเครื่องผู้ใช้ และเลือก framework ที่ใช้ CPU ได้
- ส่งมอบ: รายงานสั้นว่าแหล่งไหนใช้ได้ แหล่งไหนไม่ได้ และแผนที่ปรับตามจริง

**M1: โครงแอป**
- แผนที่ เลือกจุด กำหนดรัศมี กดรัน แล้วแสดงภาพก่อนและหลังของพื้นที่นั้น
- ส่งมอบ: แอปที่เปิดได้ด้วยคำสั่งเดียว และจับเวลาที่ใช้ต่อรัศมี 5, 10, 20 กม.

**M2: ชั้น A**
- คัดกรองพื้นที่เปลี่ยนแปลง แสดงจุดบนแผนที่ ตาราง การ์ด และ export
- ส่งมอบ: demo ที่ใช้งานได้ครบวงจร (ผลยังเป็นประเภท `disturbed` ทั้งหมด)

**M3: ชั้น B**
- สร้างชุดข้อมูลจากแหล่งเปิด ฝึกตัวจำแนก วัดผลบนชุดทดสอบ แล้วต่อเข้าแอป
- ส่งมอบ: recall บนบ่อที่กันไว้ทดสอบ และจำนวนจุดต้องสงสัยต่อพื้นที่ เทียบชั้น A กับชั้น A+B

**M4: เก็บรายละเอียด**
- วันที่เริ่มพบ ระยะถึงถนนและแหล่งน้ำ KML ประวัติการรัน และ cache ภาพที่ดึงแล้ว

## 6. การทดสอบก่อนส่งมอบแต่ละขั้น

เลือกจุดทดสอบจากข้อมูลจริง ห้ามตั้งพิกัดขึ้นเอง

1. **บ่อขยะที่รู้ตำแหน่ง:** เลือกบ่อขยะในไทยอย่างน้อย 5 แห่งจาก OpenStreetMap ที่ไม่ได้ใช้ฝึกโมเดล
   รันรัศมี 5 กม. รอบจุดที่ห่างจากบ่อ 1–3 กม. แล้วตรวจว่าบ่อนั้นอยู่ในรายการจุดต้องสงสัยหรือไม่
2. **พื้นที่ที่ไม่ควรมี:** รันในพื้นที่ป่าหรือพื้นที่เกษตรล้วน แล้วรายงานจำนวนจุดที่เสนอผิด
3. **พื้นที่ยาก:** รันในเขตเมืองและเขตที่มีงานก่อสร้างมาก แล้วรายงานจำนวนจุดที่เสนอ
4. **หน้าฝน:** รันช่วงเดือนที่เมฆมาก แล้วตรวจว่าแอปแจ้งเตือนเรื่องเมฆถูกต้อง

รายงานผลทุกข้อตามจริง รวมถึงกรณีที่บ่อขยะที่รู้ตำแหน่งไม่ถูกตรวจพบ

## 7. กติกาการทำงาน

- ผู้ใช้รัน Claude Code บน Windows (CMD) คำสั่งและ path ต้องใช้กับ Windows ได้
- ใช้ Python virtual environment แยกของโปรเจกต์ และบันทึก dependency ใน `requirements.txt`
- ทำทีละขั้น จบแต่ละขั้นให้สรุปผลและรอผู้ใช้ยืนยันก่อนไปต่อ
- ถามผู้ใช้ก่อนดาวน์โหลดข้อมูลเกิน 2 GB ต่อครั้ง
- ห้ามสร้างพิกัด ตัวอย่างฝึก หรือผลทดสอบขึ้นเอง
- รายงานตัวเลขตามจริง ถ้าขั้นไหนทำไม่สำเร็จให้บอกตรง ๆ พร้อมสาเหตุและทางเลือก
- ห้ามใช้บริการที่ต้องสมัครบัญชีหรือมีค่าใช้จ่ายโดยไม่ถามผู้ใช้
- ข้อความบนหน้าจอและรายงานเป็นภาษาไทย ชื่อตัวแปรและโค้ดเป็นภาษาอังกฤษ

## 8. ข้อจำกัดที่ต้องแสดงในแอป

- ตรวจจับได้เฉพาะกองขนาดประมาณ 30×30 ม. ขึ้นไป
- เห็นเฉพาะกองขยะกลางแจ้ง ไม่เห็นของที่อยู่ในอาคาร ฝังกลบแล้ว หรือมีพืชคลุม
- บอกไม่ได้ว่าเป็นขยะประเภทใด และบอกไม่ได้ว่าถูกกฎหมายหรือไม่
- งานก่อสร้าง บ่อดิน เหมือง และไร่ที่ไถแล้ว อาจถูกเสนอเป็นจุดต้องสงสัย
- พื้นที่ที่เมฆบังในช่วงเวลาที่เลือกไม่ได้ถูกตรวจ
- ตัวจำแนกฝึกจากข้อมูลเปิด ยังไม่เคยตรวจสอบกับข้อมูลภาคสนามของไทย
